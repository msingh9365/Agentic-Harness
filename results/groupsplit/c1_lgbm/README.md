# C1' (NOTES 30.1): LightGBM bag of API names, one April evaluation (April opening 31)

**Summary in plain English.** A model that only counts which API names occur (no order, arguments or return values; LightGBM with 300 trees, 31 leaves, learning rate 0.05, fixed in advance, trained on all of January) reaches pAUC@1e-2 **0.483** on April, against 0.686 for M1 and 0.705 for M3: about 20 points lower, resolved by the cluster bootstrap (c1 - M1 -20.4 points, cluster interval [-34.4, -7.0]; c1 - M3 -22.2, [-35.5, -9.0]); TPR@1e-3 is 0.266 (M1 0.536, M3 0.567), AUC 0.950. The gap is almost all on reports whose API sequence does not occur in January: on the April reports whose hash_apis is seen in January the bag of names is as good as the neural models (pAUC@1e-2 0.797 against 0.800 for M1 and 0.824 for M3, not resolved) but on the unseen reports it falls to 0.327 against about 0.65 (about -32 points, resolved). Under padding the bag of names is as fragile as M1 and in some sets worse: detection at the 1% threshold 24.4% / 9.9% / 3.1% under 20 / 50 / 100 random prepended calls (M1 25.4 / 7.4 / 5.7, M3 76.2 / 65.1 / 6.5), 0.5% under 200 inserted calls (M1 18.9, M3 44.3) and 0.0% under the LightGBM 50 prepend (M1 1.9, M3 35.1). Padding lowers its scores, so the padded-benign false-alarm rate is at most 0.19%. Caveats: ONE deterministic model, no seed spread (a second fit with another random_state and one thread gives identical logits, maximum difference 0.0), so std is 0 and "seeds each way" is trivial (0 up / 10 down); the LightGBM 50 prepend ranking was fitted by a LightGBM surrogate on the fold-9 training part, so for this victim it is nearly a gray-box attack; the bag of names cannot see order or position, so its padding numbers are not comparable with the window-limited neural models.
