# M3 epoch sensitivity check (NOTES 29): does anything change if M3 is trained for 2 epochs instead of 3?

**Summary in plain English.** No conclusion of the report changes. We trained M3 again for exactly 2 epochs (same code, data, tokenizer, padding and seeds as the final M3; the 2-epoch run is exactly the first two epochs of the 3-epoch run, validation logits identical) and tested it once on April, next to M1 and the final 3-epoch M3. **All three criteria that we fixed before looking were met.** (a) On clean April data the 2-epoch model is about the same: pAUC@1e-2 0.713 against 0.705 (+0.8 points, cluster interval [-0.4, +2.4], not resolved); it is a little more stable across seeds (spread 0.013 against 0.025) and a little better at the strictest threshold (TPR@1e-3 0.609 against 0.567, not resolved). (b) Against the LightGBM-chosen padding of 50 calls it still beats M1 by a wide margin: 38.8% of the malware is still detected against 1.9% for M1, a difference of +36.9 points with a cluster interval of [+23.6, +50.4] (the 3-epoch M3 has 35.1%). (c) The false alarms on padded benign reports stay low: 1.01% at 50 random prepended calls (limit 1.5%; the 3-epoch model has 0.84%). Everything else is practically the same as well: with random padding of 20 to 100 prepended calls the two M3 versions are within one point of each other (65.1% against 64.2% at 50 calls); **the cliff at 100 prepended calls is the same** (6.5% against 6.1%, the window explanation of NOTES 26.1 holds for both); the white-box greedy attack still drives both to about 2% after 50 steps (2.5% against 1.9%) and to about 49% after 20 steps (48.7% against 49.9%). The only differences that the cluster bootstrap resolves are small and point slightly towards the 2-epoch model: +3.7 points under LightGBM 50 prepend (cluster [+0.5, +6.9]) and +2.2 points under random 200 insert ([+0.1, +4.4]), against +0.1 to +0.2 points more padded-benign false alarms in several sets (still about 1% or less). The one statement that moves a little is a descriptive one about the 10-seed ensembles: the 3-epoch M3 ensemble was below the M1 ensemble in pAUC@1e-2 (-2.6 points, stratified interval excludes 0), the 2-epoch ensemble is -1.9 points with an interval [-3.9, +0.2] that includes 0; the per-seed comparison with M1 is not resolved for either version. **This is a sensitivity analysis, not a model choice: the final M3 stays the 3-epoch model unless the owner decides otherwise.** Limits: one alternative epoch count, one April set, the epoch study behind this check (NOTES 28) used two validation folds; passing the three criteria means those three statements hold, not that the two versions are identical.
