ETL Doctor an AI harness engineering project Code on GitHub

An LLM agent that diagnoses broken data pipelines, and is not trusted to fix them alone.

ETL Doctor investigates a failed pipeline inside an isolated microVM, cites every piece of evidence it used, proposes a code fix, and stops for a human. An approved fix is applied to a copy and re-tested on new and old data before anything is called fixed.

What happens in a run

intake→ sandbox→ triage→ investigate ⇄ hypothesize→ verify→ propose fix→ human approval→ validate on a copy→ report

A LangGraph state machine, checkpointed after every step: kill the process and the run resumes where it stopped. Budgets end in escalation to a human, not a crash.

Why it is safe to run unattended

  • The agent only reads: its tools run in an E2B Firecracker microVM with no internet and no secrets.
  • Every claim cites evidence IDs that the harness issued when a tool actually ran; invented IDs are rejected.
  • A fix is data (exact search/replace edits), checked by guardrails before a person sees it.
  • Nothing is applied without approval. After approval, the fix runs on a copy against current and last-good data.
  • The output is a validated patch for a human to apply. The real pipeline is never touched.
  • Logs and data from the broken system are treated as untrusted input (a prompt-injection drill is part of the repo).

How it was measured

  • 18 cases: 3 failure types × variants (date formats, column names, number styles) × crash or silent failure; 3 trials each.
  • Ground truth comes from the fault injector and is never shown to the agent.
  • Diagnosis is right in every trial; fixes vary: 16/18 cases get a working fix in some trial, 5/18 in all three.
  • An LLM judge, calibrated on labelled answers first, said 51/54 fixes looked right. Only 28 passed when run: reading a fix is not testing it.
  • A no-tools baseline scores 52/54 at a sixth of the cost on these small cases: measured, not assumed.
